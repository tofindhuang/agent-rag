# 场景记忆集：收件箱默认、每用户唯一事实、会话多选注入

Date: 2026-10-25

## Status

Accepted

## Context

FR-5 首版把 active facts 全部注入每个新会话，用户无法区分“通用偏好”和“只在某个项目/场景使用”的记忆。用户要求：场景产生的记忆可以归档，新会话按需选择复用；同时不能让所有记忆默认生效。

可选方案：每会话勾选事实、由对话自动生成集合、场景集合 + 会话多选。自动生成集合会产生碎片、提取不稳定；逐条勾选在事实多时不可用。

## Decision

1. **一个 fact 只属于一个集合**；active 唯一键保持每用户 `(user_id, category, fact_key)`，不按集合拆分。场景差异通过 key 表达。
2. **两个系统集合**：每个用户一个「通用」和一个「收件箱」；自定义集合供场景使用。系统集合不可改名/删除。
3. **新提取默认进「收件箱」**，不默认注入；现有 facts 迁移到「通用」；老会话无选择行按「通用」处理，保持兼容。
4. **会话可多选集合**：`session_profile_collections`；新会话默认只选「通用」，可显式勾选「收件箱」或场景集合；会话头部可修改，下一次 prompt 生效。
5. **删除自定义集合**：facts 移回收件箱后删除集合；不删除记忆。
6. **标题**：`profile_facts.fact_title`（≤80）由提取模型生成，缺失回退截断的 fact_text；UI 用标题作主展示，factText 作内容。
7. **注入预算**仍是选中集合合计 20 条 / 4000 字符，不按集合分配。

## Considered Options(被否的备选)

- **每会话逐条勾选事实** — 事实多时列表不可用，缺少场景复用 → 否决。
- **按对话自动创建集合** — 提取和聚类不稳定，会产生大量碎片集合 → M1 不做。
- **一个 fact 多集合** — 会让 active 唯一键、冲突消解和“同 key 多值”复杂化 → 否决。
- **新事实默认进通用** — 所有记忆仍默认生效，违背用户“不是所有记忆都会用”的诉求 → 否决。
- **删除集合同时删除 facts** — 容易误删长期记忆 → 否决。

## Consequences

- 现有用户迁移后 facts 在「通用」，行为不变；新提取先进收件箱，用户需要主动归档/勾选才会注入。
- 收件箱可能积累未整理记忆；设置页需要集合筛选和批量移动。
- 会话选择需要一个新表与两个 API；gateway 契约不变（仍接收 facts 列表）。
- 用户编辑标题/正文/分类/集合；key/value 仍不可编辑，冲突键稳定。
