# 个人数据导出：同步流式 ZIP，排除凭据与二进制

Date: 2026-10-30

## Status

Accepted

## Context

用户的数据分散在 14 张表与对象存储里，没有任何自助导出入口。M3 主题是运营与商业化，数据可携带是合规（GDPR 类）与信任的基础能力；同时它必须与既有边界一致：**凭据、他人数据、对话正文之外的内容都不能混进导出包**，而对话正文本身恰恰是用户要的。

约束：

- KB 原文在对象存储，单用户上限 1 GB；全部打包会让同步下载不可控；
- 已有 `StreamingResponseBody` 的下载先例（会话归档）；
- 审计已就位（ADR-0033），导出必须留痕。

## Decision

1. **范围**：账号资料、会话与消息、压缩摘要、记忆、知识库与文档元数据、评测标注与运行摘要、用量、自己的审计事件。
2. **排除**：密码哈希、API key（密文与提示）、refresh token、他人数据、向量、KB 原文二进制（原文已有按文档下载入口）。
3. **交付**：同步流式 ZIP（`manifest.json` + 每域一个 JSON），不落盘、不留存；`Content-Disposition` 带日期文件名。
4. **上限**：导出前估算体积（消息正文等字符量），超过 200 MB 直接拒绝（`EXPORT_TOO_LARGE`），避免流已开始再中断。
5. **频率**：每用户每天 3 次（Redis 计数，按 `app.usage.utc-offset` 切日）。
6. **二次确认**：有密码的账号需在请求体提交当前密码；OAuth-only 账号仅需登录态。
7. **审计**：成功与失败都记 `user.data.export`（失败含原因），本切片新增该动作。

## Considered Options（被否的备选）

- **异步任务 + 对象存储下载链接** — 能支持大包，但要任务表、轮询接口与产物清理；当前数据量用同步流足够 → 推迟。
- **单文件 JSON** — 无结构、体积更大、无法按域读取 → 否决。
- **包含 KB 原文** — 体积不可控且已有单独下载入口 → 否决。
- **包含密钥提示/密文** — 无导出价值且有泄露风险 → 否决。
- **不限频率** — 导出是重查询，可被用来打数据库 → 否决。

## Consequences

- 导出是只读重查询，限频 + 体积上限保护数据库；失败会在审计中留下原因。
- 包内保留用户自己的内部 id（便于比对），但不含他人的 id。
- 将来需要「大包异步导出」时，可复用同一套域查询，只改交付方式。
