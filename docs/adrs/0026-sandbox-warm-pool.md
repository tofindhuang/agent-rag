# run_code 用预热容器池降低冷启动，保持一执行一容器

Date: 2026-10-25

## Status

Accepted

## Context

M1 的 `run_code` 每次执行都创建、启动、销毁一个一次性容器。实测：

- 5 并发时容器生命周期（建/启/exec/销毁）P50 5.2s、P95 8.2s；
- 其中纯代码执行 P50 1.5s、P95 3.9s；
- 20 个 run_code 用户、全局并发 8 时，工具回传 P50 约 59s——排队占了主要部分。

FR-3 明确要求「一次执行一个容器，结束即销毁」；ADR-0017 又把准入、审计和断连语义压在一次性容器模型上；sandbox spec 明确把「容器复用」列为 out of scope。因此不能为了省几秒直接改成共享容器。

需要同时解决两件事：容器冷启动，以及全局并发 8 造成的排队。两者都不能削弱隔离边界。

## Decision

### 1. 隔离语义保持不变

- 每次执行仍然独占一个容器；执行结束（正常、超时、OOM、断连）立即强制删除。
- 池只提前创建并启动 idle 容器；被取用后即视为该次执行的容器，不回流、不复用。
- 池容器的隔离参数与执行容器完全一致：禁网、非 root、只读 rootfs、`/work` tmpfs、cap drop、pids/memory/CPU 限制。

### 2. 预热池

- 应用就绪后异步填池，`target` 默认 12、`max` 默认 16；填充完成前来的执行直接冷创建。
- 取池是原子操作；取到后 `inspect` 确认 running，否则丢弃并尝试下一个/冷创建。
- 池空不等待，直接冷创建；补池最多 2 个并发创建，失败指数退避（1s→2s→5s，上限 30s）。
- idle 超过 10 分钟的池容器销毁重建；镜像 ID 变化时丢弃旧池容器。
- JVM 启动时删除上一进程遗留的 `role=pool` 容器；`SandboxMaintenance` 不按一次性容器年龄规则误杀池容器，只清理超过 2×idle TTL 的失管池容器。

### 3. 并发与准入

- 全局并发默认从 8 提到 12；per-user 仍为 2；排队上限仍为 120s。
- 准入仍同步等待 permit；本轮不引入异步准入。
- 12 是 16GB 参考机上「20 个 run_code 两波完成、CPU 不过度超卖」的折中；更高并发留给后续异步准入与容量评估。

### 4. 降级

- 池只是加速层：池空、容器坏、补池失败都退回冷创建。
- 冷创建也失败才返回 `SANDBOX_UNAVAILABLE`；池管理器自身失败不阻塞聊天或其他工具。
- 生产默认开启，`SANDBOX_POOL_ENABLED=false` 可完整回退到 M1 行为；测试环境默认关闭。

### 5. 审计与可观测

- 审计仍是一执行一条 `exec_records`；池容器的创建不是执行，不写审计。
- 指标/日志：idle、creating、checkout wait、cold fallback、replenish failures、执行容器生命周期耗时。
- Docker client 连接数按「globalConcurrency + poolMax + stats/补池余量」上调，避免池与执行争连接。

## Considered Options(被否的备选)

- **同容器串行复用** — 省掉建容器，但后台进程、文件描述符、Python 模块状态和 `/work` 残留都可能跨执行泄漏；隔离从一次性降为「清理后共享」，需要改 FR-3 与新安全 ADR。收益只有几秒，不值得。
- **每用户长驻容器** — 性能最好，但同一用户内不隔离；多租户下不符合「执行间无残留」的承诺。
- **不改容器模型，只提并发** — 改动最小，直接针对 59s 的主要成分，但冷启动 5–8s 仍在；D 与预热池一起做才覆盖两段延迟。
- **池空时等待补池** — 稳态可能少一次冷创建，但把池的延迟不确定性带进执行路径；冷创建兜底更可预测。
- **只做异步准入** — 解决排队占线程，不解决冷启动；且会重做 SSE 开流/错误/断连语义，超出本轮。
- **AIO Sandbox 作为底座** — ADR-0003 已否决；与禁网、一次性执行冲突。

## Consequences

- 池会长期占用最多 12–16 个 idle 容器；512MB 是上限不是预分配，但宿主机仍需为容器开销留余量。
- 执行路径多一层池管理器：取池、健康检查、补池、TTL、镜像变化、崩溃清理都需要测试与指标。
- 全局并发 12 会增加同时执行的容器数与 CPU 竞争；16GB 参考机之外的部署必须自行调低 `SANDBOX_GLOBAL_CONCURRENCY` / 池大小。
- 预热池不改变 `exec_records`、SSE 帧、错误码与断连语义；契约不需要升级。
- 若目标 P50≤10s / P95≤25s 未达成，优先调池 target/并发，而不是退回容器复用。
