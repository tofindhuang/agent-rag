涉及模块：server、gateway、web、契约、docs

## 范围

M3 的主题是「从能跑变成能运营」。本阶段交付四件事：

1. **用量配额**：每用户每月 token 上限，超额 429 `QUOTA_EXCEEDED` 并给出重置时间。
2. **审计日志**：登录/凭证/密钥/破坏性操作的元数据留痕，用户看自己的、admin 看全部。
3. **个人数据导出**：流式 ZIP，含文本数据，排除凭据与二进制原文。
4. **会话分支 UI**（原 FR-1 P2）：「从这里重新开始」，隐藏旧分支而不删除。

## 设计约定（后续改动必须遵守）

- **配额**：`QUOTA_MONTHLY_TOKENS` 默认 0（不限）；判定在 `openPrompt`、先于 TPM；在飞轮次不打断；判定路径不读缓存。
- **审计**：只记元数据（`detail` ≤2KB），永不记正文/密钥/token；写入 best-effort，失败计数不阻塞业务；保留 180 天。
- **导出**：只含本人数据；流开始前完成体积与频率检查；有密码的账号需二次确认；导出本身写审计。
- **分支**：靠 pi entry id 对齐，不按文本/序号猜；旧消息 `active_branch=0` 保留；分支不生成摘要、不计配额。

## 明确未做（M3 之外）

| 项 | 去向 |
|---|---|
| admin 写操作（调额、禁用用户、强制登出） | **按需再开**；审计已就绪，是最小依赖 |
| per-user 配额覆盖 | 依赖 admin 写操作 |
| 成本配额 / 次数配额 / per-KB 拒答阈值 | 明确的第二维度，等对应前提（价格覆盖完整、多库差异诉求） |
| 真实语料 50+ 评测标注 | 数据项，流程见拒答验收记录 |
| 完整分支树 / 分叉摘要 | 分支 UI 的下一阶段 |
| 多语言沙箱（O3）、AIO workspace（O4）、gVisor 实测 | 平台向后续 |

## 生产化缺口（本阶段未覆盖，建议作为下一主题）

1. **部署交付**：只有开发用 `docker-compose`，没有 Helm/K8s、镜像发布与回滚方案；
2. **备份与灾备**：MySQL / Qdrant / 对象存储均无备份脚本或恢复演练；
3. **告警与 SLO**：只暴露 Prometheus 指标，没有告警规则与值班流程；
4. **密钥管理**：模型密钥以 AES-GCM 存库，主密钥来自环境变量，未接 KMS/Vault；
5. **数据生命周期**：对象存储归档自动过期、日志与审计归档未做；
6. **企业能力**：MFA、SCIM、多 OIDC provider 未做；
7. **i18n / 无障碍 / 移动端**：中文硬编码、桌面优先。

## 承诺边界

- 配额是**部署级默认**，不是计费系统：没有账单、没有按量结算、没有退款语义。
- 审计是**观测**，不是合规级不可篡改日志（无 WORM、无外部归档）。
- 导出是**同步流**，单包上限 200MB；超过请先清理会话。
- 分支只支持「回退并重新开始」，不支持在多条分支间切换。

## 下一步建议

1. 生产化主题（部署 + 备份 + 告警）——决定「能不能上生产」；
2. O3 多语言沙箱顺序的决策（一次 grilling 即可，不必立刻实现）；
3. 完整分支树（有真实需求时）。
