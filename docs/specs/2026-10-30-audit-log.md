# M3 切片 2：审计日志

日期：2026-10-30
状态：已实现并验收（见 `docs/research/2026-10-30-audit-acceptance.md`）
关联 ADR：[0033](../adrs/0033-audit-events.md)、[0023](../adrs/0023-observability-mysql-read-only-admin.md)、[0030](../adrs/0030-token-bucket-rate-limit-and-trusted-proxies.md)
关联需求：FR-6（安全）、FR-7（运营）
涉及模块：server、web、docs

## Problem Statement

密码/密钥变更、破坏性删除、登录失败与 refresh 重用检测都没有可回溯的记录；admin 只读看板只有聚合数。M3 后续的配额覆盖与数据导出也缺少可追责的底座。

## Solution

- 新增 `audit_events` 表与 `AuditService`，在用例边界显式记录三类事件（认证与凭证、密钥与配置、破坏性操作）。
- 写入 best-effort：失败只 warn + 计数，绝不影响业务；同时输出结构化日志。
- 用户设置页展示自己的安全事件；admin 新增只读审计列表（元数据，按动作/操作者过滤）。
- 每天清理 180 天前的记录。

## Implementation Decisions

### 1. Schema

```sql
CREATE TABLE IF NOT EXISTS audit_events (
    id BIGINT NOT NULL AUTO_INCREMENT,
    actor_user_id BIGINT NULL,
    actor_type ENUM('user','admin','system','anonymous') NOT NULL,
    action VARCHAR(64) NOT NULL,
    target_type VARCHAR(32) NULL,
    target_id VARCHAR(64) NULL,
    outcome ENUM('success','denied','failed') NOT NULL,
    ip VARCHAR(64) NULL,
    user_agent VARCHAR(255) NULL,
    detail JSON NULL,
    created_at DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    PRIMARY KEY (id),
    KEY idx_audit_actor_created (actor_user_id, created_at),
    KEY idx_audit_action_created (action, created_at)
)
```

- up-only、幂等、无 down；`actor_user_id` 不设外键（用户删除后审计仍需保留）。

### 2. 动作清单（固定枚举字符串）

| 分组 | action |
|---|---|
| 认证 | `auth.register`、`auth.login`、`auth.login.failed`、`auth.refresh.reuse`、`auth.logout.all` |
| 凭证 | `auth.password.set`、`auth.password.change`、`auth.identity.link`、`auth.identity.unlink` |
| 配置 | `model.provider.create`、`model.provider.update`、`model.provider.delete`、`model.provider.default`、`kb.settings.update`、`kb.settings.reset`、`kb.threshold.update` |
| 破坏性 | `session.purge`、`session.archive`、`session.restore`、`kb.document.delete`、`kb.delete`、`memory.fact.delete` |

- `target_type/target_id` 例如 `session/<uuid>`、`provider/<id>`、`document/<uuid>`。
- `detail` 只放摘要字段（如 `{"changed":["apiKey"]}`、`{"reason":"..."}`），≤2 KB。

### 3. 写入

- `AuditService.record(action, outcome, actorUserId, actorType, targetType, targetId, detail)`
- IP/UA 从 `RequestContextHolder` 取（无请求上下文时为 null）；IP 复用 `ClientIpResolver`。
- 失败：`log.warn` + `agentcore_audit_write_failures_total`，不抛出。
- 每次成功写入同时 `log.info`（logger `audit`）输出一行 JSON。

### 4. 读取

- `GET /api/audit/me?limit=20`：当前用户自己的事件（所有类型，含配置变更），按时间倒序。
- `GET /api/admin/audit?limit=50&beforeId=&action=`：admin 只读，返回元数据。
- 两者都不返回 `detail` 中的敏感字段（本就没有）与正文。

### 5. 前端

- 设置页「安全事件」：最近 20 条，显示时间/动作中文名/结果/目标；失败事件标红。
- admin 页新增「审计」Tab：表格 + 动作筛选 + 分页（游标）。

## Out of Scope

- 审计导出（随「数据导出」切片）、实时告警、审计的 WORM/防篡改；
- admin 写操作；
- 对每条消息/每次检索的审计。

## Acceptance

1. 登录成功/失败、改密、换 key、删文档、purge 会话都会产生一条 `audit_events` 记录，且 `detail` 不含密钥/正文。
2. 审计写入失败（模拟 DAO 抛错）不影响业务成功，计数器 +1。
3. 用户只能读自己的事件；admin 能读全部（只读）。
4. 180 天前的记录被每日任务清理。
5. 设置页与 admin 审计页可用；typecheck/build 通过。
