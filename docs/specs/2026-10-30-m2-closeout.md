1. **限流调优**：固定窗口 → 令牌桶（消除窗口边界 2× 突刺、`Retry-After` 按补充速率计算）；新增可信代理白名单，代理后按真实客户端 IP 限流。

3. **M2 closeout**：汇总各切片证据、补齐轻量滚动重启冒烟、明确未覆盖项与承诺边界。

## 承诺边界（必须与 README 一致）

- **不断流**只覆盖「排空式滚动更新」：实例收到 drain 后拒绝新轮次、等在飞轮次完成再退出。
- **崩溃与强杀仍是 `partial`**：进程被 kill -9 时，在飞轮次只能落成 `partial`，由下一次继续。
- 单机多实例：共享 `GATEWAY_SESSION_DIR` 与 Redis，**不含**跨主机、网络文件系统、K8s。
- 限流是**单实例令牌桶 + 共享 Redis**：多实例下配额一致；Redis 故障 fail-open。
- 可信代理白名单为空时不解析 `X-Forwarded-For`；部署在代理后必须配置，否则认证 IP 配额会全站共享。
- 沙箱隔离是「runc + 禁网 + 只读根 + 非 root + cap-drop + 资源上限」，**不是绝对边界**（R2）；gVisor 未启用。

## 残余风险

- 200×5 压测报告对应的是 2026-10-25 的 commit；本轮只做轻量冒烟覆盖改动面，不重跑全量。
- 令牌桶允许「瞬时用满容量」，与固定窗口的「窗口内硬上限」语义不同；配额含义变化需要运营侧知晓。
- gVisor 结论未实测。
