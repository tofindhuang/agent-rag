# 聊天界面 Markdown 渲染与排版优化

日期：2026-10-25
状态：已与用户对齐（Phase 1 完成），待实现
关联：ADR-0012（设计 token / 对比度门禁）；`web/README.md`（分层规范）

## Problem Statement

助手回复目前以纯文本渲染：Markdown 语法（标题、列表、代码块、表格、链接）原样显示，长回复可读性差；聊天主区的气泡、间距、工具卡片、引用与输入区排版偏拥挤、层级不清，整体观感不像一个成熟产品。用户希望优化排版，并让助手输出正确渲染 Markdown。

## Solution

- 助手消息用 Markdown 渲染（GFM：表格、任务列表、删除线、自动链接），流式过程中实时渲染；用户消息保持纯文本并保留换行。
- 重做聊天主区视觉：sticky 顶栏、助手消息去气泡化、用户气泡右侧、统一消息间距与字号、工具/引用卡片化、空状态与输入区（自动增高多行输入、Enter 发送 / Shift+Enter 换行）。
- 只使用现有语义 token，保持深/浅色主题与对比度门禁通过；不引入语法高亮（后续可加）。

## User Stories

1. 作为用户，我希望助手回复中的标题、列表、代码块、表格、链接正确排版，以便快速阅读。
2. 作为用户，我希望流式输出期间也能看到接近最终的排版，而不是先看到一堆 `**` 和 `-`。
3. 作为用户，我希望长回复有舒适的行宽、行高与段落间距。
4. 作为用户，我希望代码块有独立背景、横向滚动与一键复制。
5. 作为用户，我希望工具调用与引用以紧凑卡片呈现，不打断正文阅读。
6. 作为用户，我希望输入框支持多行（Shift+Enter 换行），并随内容自动增高。
7. 作为用户，我希望发送/停止按钮与输入区对齐、聚焦态清晰。
8. 作为用户，我希望深色/浅色主题下 Markdown 与卡片都有足够对比度。
9. 作为用户，我希望移动端侧边栏折叠后聊天区仍有合理留白与可读行宽。
10. 作为维护者，我希望新增依赖精确锁定、样式只用语义 token，并通过现有 token/对比度门禁。

## Implementation Decisions

- 新增 `react-markdown@10.1.0` 与 `remark-gfm@4.0.1`（精确版本）。默认不解析原始 HTML（不引入 `rehype-raw`），链接强制 `target="_blank" rel="noopener noreferrer"`。
- 仅助手消息走 Markdown；用户消息保持 `white-space: pre-wrap` 纯文本，避免用户输入的多行被折叠。
- 流式期间实时渲染（react-markdown 对未闭合语法容错）；流式末尾显示光标。
- 代码块：`pre` 自定义渲染，等宽字体、独立背景、横向滚动、复制按钮（`navigator.clipboard`，失败静默）；不做语法高亮。
- 表格：外层横向滚动容器，表头使用 surface 背景。
- 排版：助手消息去掉气泡背景、占满内容列；用户气泡右对齐、圆角不对称；顶栏 sticky + 半透明背景；消息间距加大；工具/引用改为卡片。
- 输入区：`textarea` 自动增高（上限约 200px），Enter 发送、Shift+Enter 换行，组合输入（输入法）不触发发送；保留现有 `aria-label="消息输入"`。
- 样式只消费语义 token（ADR-0012）；新增 token（如代码块背景）只加在 `globals.css`。
- 不做语法高亮、不改设置页/知识库页、不做品牌换肤。

## Testing Decisions

- 门禁：`npm run typecheck`、`npm run build`、`npm run check:tokens`、`npm run check:contrast`。
- 浏览器验收（Playwright，真实栈）：助手回复中出现标题/列表/代码块/表格/链接且样式生效；复制按钮可用；流式期间渲染不崩；用户多行消息保留换行；停止按钮行为不变；深/浅色主题截图检查。
- 不新增单元测试框架；该改动的可测面是构建门禁与浏览器行为。

## Out of Scope

- 语法高亮、Markdown 编辑器、富文本输入。
- 设置页、知识库页、登录页的视觉改版。
- 全站品牌/配色重设计。

## Further Notes

- react-markdown 的 `components` 映射集中在一个 `MarkdownContent` 组件，便于以后替换渲染器或加高亮。
- 流式渲染的性能在消息长度可控范围内可接受；若后续长回复出现卡顿，可在 `message_end` 前降级为纯文本。
